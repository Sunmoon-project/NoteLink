# 홈 화면과 공부 시간

현재 코드 기준으로 홈 화면의 기능, 데이터 흐름과 확인이 필요한 부분을 정리한다. 화면 코드는 `apps/mobile/src/features/session/home.tsx`, 홈 탭 진입점은 `apps/mobile/app/(tabs)/(home)/index.tsx`다.

## 기술 스택과 역할

- **Expo · React Native · TypeScript**: 홈 화면, 버튼과 입력창을 구성한다. Expo Router로 친구, D-day, 학습 기록, 가로 모드와 공부 결과 화면에 이동한다.
- **TanStack React Query**: 오늘 기록, 주간 기록·목표, D-day와 내 정보를 조회하고 캐시한다. 항목 추가와 세션 종료 후 관련 데이터를 다시 조회한다.
- **Zustand**: 현재 공부 항목, 세션 ID, 시작·일시정지 시각과 진행 중 경과 시간을 앱 메모리에서 관리한다(`apps/mobile/src/stores/session.ts`).
- **Expo Sensors · Keep Awake · Haptics**: 기기 기울기를 감지해 탁상 모드로 이동하고, 측정 중 화면을 유지하며, 항목 버튼에 진동 피드백을 준다.
- **React Native Reanimated**: 목록과 카드의 등장·이동 애니메이션에 사용한다.
- **NestJS · REST API**: 로그인 사용자의 공부 항목과 세션, 주간 목표·기록, D-day, 프로필을 처리한다. 홈 타이머는 매초 Socket.IO나 HTTP 요청을 보내지 않는다.
- **MongoDB · Mongoose**: 하루 기록(`daily_records`), 세션(`study_sessions`), 과목과 주간 목표 등을 저장한다. 세션 생성·종료의 트랜잭션에는 복제 세트 또는 mongos가 필요하다.
- **공유 계약**: `packages/shared/src/contracts.ts`의 경로와 공유 타입을 앱과 서버가 함께 사용한다.

## 홈 화면 기능

- **인사와 연속 학습일**: 내 정보에서 닉네임과 `streakDays`를 가져온다. 서버는 서울 기준으로 하루 순공 10분 이상인 날짜의 연속 여부를 계산한다.
- **D-day와 친구**: 조회한 D-day 중 남은 일정이 있으면 홈에 보여 주고, 각각 D-day·친구 화면으로 이동한다. 현재 D-day 카드는 공부 항목이 있을 때 표시된다.
- **오늘 공부할 목록**: 오늘 기록의 `items`를 보여 준다. 항목 추가 시 제목, 과목명과 선택한 목표 시간을 서버에 저장한다. 항목별 시작·일시정지 버튼과 시간을 표시한다.
- **공부 측정**: 선택 항목의 시작·일시정지·재개·종료를 지원한다. 측정 중 큰 타이머는 해당 항목을 보여 주고, `오늘 전체`는 아래에 표시한다. 일시정지 상태가 10분을 넘으면 화면의 자동 종료 처리를 시도한다.
- **주간 목표와 학습 기록**: 목표 시간과 80% 알림 설정을 조회·저장하고, 주간 누적 시간과 목표 달성률을 표시한다. `weekly-progress.ts`는 반올림 전의 실제 시간으로 80% 도달 여부를 계산한다. 학습 기록 카드를 누르면 기록 화면으로 이동한다.
- **탁상 모드**: 기기 설정에서 탁상 모드가 켜져 있으면 가속도 센서로 가로 방향을 감지해 가로 화면으로 이동한다.
- **연결·오류 안내**: 네트워크 배너와 오늘 기록·주간 기록 재조회 버튼을 제공한다. 시작·종료 요청이 실패하면 안내 메시지를 보여 준다.

## 데이터와 API 흐름

모든 주소의 공통 접두사는 `/api/v1`이고 공부 관련 요청은 로그인 인증이 필요하다. 기본 앱 설정은 서버 API를 사용하며 `EXPO_PUBLIC_USE_LOCAL_DATA=true`일 때만 기기 내 로컬 데이터를 쓴다.

| 동작 | API | 결과 |
| --- | --- | --- |
| 오늘 기록 | `GET /study/today` | 서울 기준 오늘의 `totalSec`, `items` 등을 반환한다. 기록이 없으면 빈 기록을 만든다. |
| 항목 추가 | `POST /study/items` | 오늘 `daily_records.items`에 항목을 넣는다. |
| 과목 조회 | `GET /subjects` | 활성화된 과목 목록을 가져온다. |
| 공부 시작 | `POST /study-sessions` | 항목 소유 여부를 확인하고 `study_sessions`에 세션을 만든다. |
| 일시정지·재개 | `POST /study-sessions/:id/pause`, `POST /study-sessions/:id/resume` | 세션 상태와 일시정지 구간의 시각을 기록한다. |
| 종료 | `POST /study-sessions/:id/end` | 서버 시각으로 순공시간을 계산해 하루 기록과 항목에 반영하고 해당 보상을 처리한다. |
| 주간 기록·목표 | `GET /study/weekly`, `GET /goals/weekly`, `PUT /goals/weekly` | 주간 요약과 목표·알림 설정을 조회하거나 저장한다. |
| 기타 | `GET /users/me`, `GET /ddays` | 닉네임·스트릭과 D-day를 가져온다. |

공부 중 앱은 저장된 오늘 전체 시간 `totalSec`에 기기에서 계산한 현재 세션의 오늘 경과 시간을 더해 화면을 1초마다 갱신한다. 항목별 표시는 해당 항목의 누적 시간을 기준으로 한다. 서버 요청은 시작·일시정지·재개·종료 시점에 발생한다. 종료 후 홈에서 공부 기록을 다시 조회한다. 서버 저장은 UTC 시각을 사용하고, 오늘의 경계는 서울 자정이다.

## 현재 제한과 확인할 점

1. **화면 시간의 지연 가능성**: 앱은 서버의 시작 성공 응답을 받은 뒤 기기 시각으로 타이머를 시작한다. 서버의 시작 시각과 화면의 기준 시각 사이에는 요청·응답 시간만큼 차이가 생길 수 있다. 일시정지·재개도 응답 후 화면 상태를 바꾼다.
2. **일시정지 시 누적 시간**: 현재 서버는 일시정지 구간을 세션에 기록하지만 `daily_records` 누적 시간은 세션 종료 시 정산한다. 일시정지마다 누적 저장하는 방식은 아직 적용되지 않았다.
3. **자정을 넘긴 항목**: 홈과 종료 결과의 전체 시간은 `totalSec`으로 표시한다. 서버는 자정을 넘긴 세션의 다음 날 시간을 다음 날 전체 기록에 저장하지만, 해당 시간을 다음 날 공부 항목에 연결하지는 않는다.
4. **80% 알림**: 공부 중이고 알림이 켜져 있으면 이 기기에 도달 예정 시각을 예약한다. 일시정지·종료·목표 변경 시 예약을 취소하거나 다시 잡는다. 알림을 누른 후 확인 버튼을 눌러야 서버의 해당 주 `notified80`이 true가 된다. 이 방식은 기기별 로컬 알림이라 여러 기기 간 예약 중복은 방지하지 못하며, 다른 기기에서 세션을 바꾸거나 목표를 바꾼 경우 잠긴 기기의 예약이 즉시 취소된다는 보장도 없다. 실제 아이폰 잠금 화면과 알림 권한은 기기에서 확인해야 한다.
5. **새 과목**: 항목 추가 시 새 과목명을 기록하지만, `StudyService.addItem()`은 기존 과목을 조회할 뿐 새로운 `subjects` 문서를 만들지 않는다. 새 이름이 과목 선택 목록에 재사용되도록 저장되는지는 별도 구현 확인이 필요하다.
6. **앱 종료와 복구**: 진행 중 세션의 앱 상태는 메모리에 있다. 앱이 강제 종료된 뒤 이전 타이머를 화면에서 복원하는 경로는 확인되지 않았다. 서버는 이후 새 세션을 시작할 때 기존 열린 세션을 정산하도록 구현돼 있다.

## 확인 방법

1. 로그인 후 항목을 추가하고 홈의 목록에 보이는지 확인한다.
2. 항목을 시작하고 일시정지·재개·종료한 다음, 홈과 결과 화면의 시간 및 재진입 후 기록을 확인한다.
3. 다른 항목으로 전환하고, 앱 백그라운드 복귀와 서울 자정 경계도 확인한다.
4. 주간 목표 저장과 재조회, D-day·친구·학습 기록 이동 및 기기 기울기 동작을 확인한다.
5. 회귀 테스트: `npm run test -w apps/mobile -- --runInBand --watchman=false --forceExit timer-review-regression.test.tsx timer-second-review.test.tsx`. 서버 단위 테스트: `npm run test -w apps/api -- study.test.ts`.

자동 테스트는 실제 아이폰·네트워크·운영 환경 검증을 대체하지 않는다.
