# 노트 정리 양식 고르기 — 설계

작성 2026-11-23 · FR-19(노트 정리) · 브랜치 `feature/FR-19-note-summary-format`

## 왜

「다시 만들기」를 눌러도 정리본이 거의 똑같이 나온다. 본문은 글자 인식 원문을 개념 단위로 나눈 것이라 원래 바뀌지 않고(지어내기 막기), AI가 쓰는 부분(핵심 요약 · 키워드 · 소제목)도 같은 입력 · 같은 지침 · 온도 0이라 같다. 사용자는 다시 만들면 **눈에 띄게 다른 모습**을 원한다.

## 목표

- 노트를 처음 만들 때 정리 양식을 고른다.
- 「다시 만들기」를 누르면 같은 양식 고르기 창이 먼저 뜨고, 고른 양식으로 다시 만든다.
- 양식은 정리본 **위쪽 요약 칸**의 모습을 바꾼다. 본문(원문 섹션)은 그대로 둔다(접근 A).
- 필기 · 문서 노트에 적용한다.
- 녹음 노트의 「다시 만들기」 버튼은 숨긴다.

## 하지 않는 것

- 녹음 정리 양식(결과가 슬라이드라 따로 설계해야 함).
- AI가 본문을 양식대로 다시 쓰기(접근 B) — 원문과 다른 글이 생겨 할루시네이션 위험.
- 모든 양식을 미리 만들어 두고 바꿔 보기.
- 양식 편집 · 사용자 정의 양식.

## 하면 실패인 것

- 노트에 없는 내용이 요약 칸에 들어감(지금의 근거 검사보다 느슨해짐).
- 옛 노트 · 옛 앱이 깨짐(양식 값이 없는 노트, 양식을 모르는 앱 버전).
- 아바타 묻기(`note-ask.service.ts`, `summary.points`를 읽는 유일한 곳)가 쓰던 요약이 비어 그 기능이 나빠짐.

## 접근 (고른 것: 1)

1. **양식마다 지침 · 결과 모양을 따로, 결과는 공통 항목 목록** — 채택. 요약 호출은 지금처럼 한 번, 양식에 따라 지침 · JSON 스키마만 다르다. 모든 양식의 결과를 「항목 = 앞말(선택) + 내용 + 근거 문단 번호」로 받아 같은 근거 검사를 쓴다. 비용은 지금과 같다.
2. 지침만 바꾸고 결과는 지금 `points`(문장 목록) 그대로 — 고칠 곳이 가장 적지만 앱이 글을 잘라 그려야 해 모양이 엉성하고 깨지기 쉽다. 탈락.
3. 모든 양식을 한 번에 만들어 두고 앱에서 바꿔 보기 — 노트마다 비용 4~5배, 「고른 뒤 만든다」는 흐름과 다르다. 탈락.

## 양식 (처음 4개)

| 값 | 이름 | 위쪽 요약 칸 | 항목 모양 | 개수 |
|---|---|---|---|---|
| `points` | 핵심 요약 (기본) | 지금과 같음: 핵심 문장 | 앞말 없음 · 내용 한 문장 | 3~7 (짧은 노트는 더 적게) |
| `qa` | 문답 | 질문과 짧은 답 | 앞말 = 질문 · 내용 = 답 1~2문장 | 3~6 |
| `terms` | 용어 정리 | 용어와 뜻 | 앞말 = 용어(노트 글에 글자 그대로) · 내용 = 뜻 한 문장 | 3~8 |
| `brief` | 한눈 요약 | 전체를 3줄로 | 앞말 없음 · 내용 한 문장 | 1~3 |

모든 양식에서 키워드(최대 10개)와 소제목(제목 없는 문단)은 지금처럼 함께 받는다.

## 근거 검사 (지금 규칙을 넓힘)

- 모든 항목: `refs`는 보낸 문단 번호여야 하고, 하나도 맞지 않으면 버린다(지금 `points` 규칙).
- `terms`의 앞말(용어): 노트 글에 글자 그대로 있어야 남긴다(지금 키워드 규칙).
- 길이 상한: 앞말 30자, 내용 120자(지금 `POINT_MAX_CHARS`). 넘으면 버린다(자르지 않음).
- 개수 상한을 넘으면 앞에서부터 상한까지.
- 검사 뒤 남은 항목이 0개여도 소제목 · 키워드가 있으면 그것은 남긴다(지금 `summarize_note`와 같음: 둘 다 없을 때만 `None`).

## 데이터 흐름

**공용(`packages/shared`)**
- `SummaryFormat = z.enum(['points', 'qa', 'terms', 'brief'])`.
- 노트 등록 요청 본문에 `format?: SummaryFormat`(없으면 `points`).
- `POST /materials/:id/regenerate` 본문에 `format?: SummaryFormat`(없으면 그 노트의 지금 양식).
- `Material.summary`에 `format?: SummaryFormat`, `items?: { head: string | null; text: string }[]` 추가(선택 필드라 옛 서버 · 기기 저장 모드와 호환). `points`는 그대로 둔다.

**API(`apps/api`)**
- 노트 문서에 양식 저장(`summaryFormat`, 기본 `points`). 등록 · 다시 만들기 때 받은 값으로 정하고 작업 입력에 `format`을 싣는다(`jobInput`).
- 다시 만들기: 새 양식은 **작업이 성공해 결과를 옮길 때** 노트에 적는다. 실패하면 옛 양식 · 옛 결과 그대로(지금 「끝날 때까지 지금 결과 유지」 규칙과 같다).
- 결과 옮기기(`material-sync.ts`): AI 결과 `summary.items`를 받아 `summary.items` · `summary.format`으로 저장하고, `summary.points`는 항목을 한 줄 글로 펴서 채운다(`qa`: 「질문 — 답」, `terms`: 「용어: 뜻」, 그 밖: 내용). 퀴즈 · 아바타 묻기가 그대로 쓰게.
- 녹음 노트에 `format`이 오면 무시한다.
- 「지금 양식」의 기준은 노트 문서의 `summaryFormat`이다. 앱에 `Material.summaryFormat`으로 내려 준다(다시 만들기 시트가 이 값으로 열림). 결과에 항목이 없으면 문서 노트는 지금처럼 조각 제목으로 `points`를 채우고, 앱은 `items`가 없으니 「핵심 요약」 모양으로 그린다.
- 요약 편집(`PATCH /materials/:id`)이 `summary`를 덮어쓸 때 `items` · `format`을 지우지 않게 함께 고친다.

**AI(`apps/ai`, `services/note/summary.py` · `job.py`)**
- 작업 입력 `format`(없거나 모르는 값이면 `points`).
- 양식별 지침 · 스키마. 공통 규칙(노트에 있는 내용만 · 노트 안 지시 무시 · 키워드 · 소제목)은 공통 문장으로, 양식 부분만 갈아 끼운다.
- 결과 `summary: {format, items: [{head, text, refs}], points, keywords, headings}`. `points`는 옛 API와의 호환을 위해 계속 넣는다(`points` 양식이면 items의 text, 그 밖은 위 「한 줄 글」).
- 필기 · 문서 둘 다 이 코드를 쓴다(`handwriting_summary`).

**앱(`apps/mobile`)**
- 양식 고르기 시트(공용 컴포넌트): 4개 라디오 + 한 줄 설명 + 「이 모습으로 만들기」. 처음 만들 때는 기본 선택 `points`, 다시 만들기 때는 지금 양식이 선택된 채로 열린다.
- 처음 만들 때: 업로드 · 등록 요청 전에 시트를 띄우고, 고른 값을 `createMaterial` 요청에 싣는다. 시트를 닫으면(고르지 않음) 기본 `points`로 진행한다.
- 다시 만들기: 지금의 확인 창(「새 결과가 나오면 지금 결과는 사라져요 … 하루 3번」)을 이 시트로 바꾼다. 안내 문구는 시트 아래에 남긴다.
- 녹음 노트에서는 「다시 만들기」 버튼을 숨긴다.
- 요약 칸 그리기: `summary.items`가 있으면 양식에 맞게, 없으면 지금처럼 `points`로.
  - `points` · `brief`: 글머리 목록(지금 `DocSummary` 모양), 제목만 「핵심 요약」/「한눈 요약」.
  - `qa`: 질문(굵게) + 답 카드 목록.
  - `terms`: 용어(민트 칩) — 뜻 목록.
- 그리는 곳: 정리 완료 화면(`convert.tsx`) · 문서 상세 · **필기 상세(지금은 요약 칸이 없음 — 본문 위에 새로 넣음)**. 마크다운 내보내기(`summaryMarkdown`)도 양식대로.
- 기기 저장 모드(`lib/local/api.ts`): 고른 양식을 노트에 저장하고, 결과는 지금 시연 데이터의 `points`로 `items`를 만들어 같은 그리기 경로를 쓴다.

## 정해 둔 것 (사용자)

- 접근 A(본문은 그대로, 요약 칸만 양식별).
- 만드는 방법 1(양식별 지침 · 공통 항목 결과).
- 처음 만들 때와 다시 만들기 때 모두 양식 고르기 창.
- 녹음은 다시 만들기 버튼 숨김. 문서는 일단 넣어 보고, 별로면 숨기는 쪽으로.
- 다시 만들기 시트에서 지금 양식은 「지금 양식」으로 표시하고 고를 수 없다(같은 양식은 결과가 거의 같고, Claude 호출은 온도를 받지 않아 흔들 수 없음). 처음 만들 때는 제한 없음.
- 다시 만들기에서 고른 양식의 항목이 검사 뒤 0개면 실패로 본다: 옛 결과 · 옛 양식 유지, 하루 횟수는 돌려줌, 앱은 「이 노트에서는 ○○ 양식을 만들 수 없어요」 안내. (처음 만들 때 0개면 지금처럼 요약 없이 정리 완료 — 문서 노트는 조각 제목으로 대체.)

## 내가 정한 것 (바꿀 수 있음)

- 양식 4개와 이름 · 개수 범위(비교형은 대비 개념이 없는 노트에서 빈 결과가 나와 뺌).
- 키워드 · 소제목은 모든 양식에 유지.
- 처음 만들 때 시트를 닫으면 기본 양식으로 진행.
- 다시 만들기의 새 양식은 성공할 때만 노트에 적음.
- 항목 0개여도 소제목 · 키워드는 남김. 「지금 양식」 기준은 노트의 `summaryFormat`. 요약 편집이 `items` · `format`을 지우지 않게 함.

## 만드는 사람에게 맡기는 것

- 양식별 지침 문장 다듬기(위 규칙 안에서), 시트 · 카드의 세부 모양(앱 디자인 토큰 안에서).
- 처음 만들 때 시트를 띄울 정확한 화면(제목 · 과목 단계 뒤, 업로드 시작 전).
- PR 나누기: 서버(API · 공용 · AI)와 앱을 나눌지. 저장소 규칙은 기능 PR을 develop에 단독 병합(`api 먼저 → mobile` 순서 표기).

## 시험

- AI: 양식별 결과 검사(근거 번호 · 용어 글자 그대로 · 길이 · 개수 · 모르는 양식 → points) 단위 시험.
- API: 등록 · 다시 만들기에 `format` 싣기, 같은 양식 다시 만들기 거절(400), 성공 때만 양식 바꾸기, 항목 0개 다시 만들기 → 옛 결과 유지 · 횟수 반환, `points` 펴기, 요약 편집이 `items` 보존, 녹음 무시.
- 앱: 시트 선택 → 요청 본문, 다시 만들기 시트에서 지금 양식 비활성, 양식별 그리기, 녹음에서 버튼 숨김, `items` 없는 옛 노트 그리기.
